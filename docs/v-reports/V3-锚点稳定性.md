# V-3 技术验证：锚点稳定性

**方法**：检查 Content v3 为文档标题生成 anchor 的方式；测试标题改动、文件重命名后 anchor 是否保持稳定。

**判据**：Owner 未裁（D2），只报告实测值。

**运行时间**：2026-11-11

## Content 标题 anchor 生成规则（实测）

从 Content v3 dist 源码（`@nuxt/content/dist/runtime/internal/query.js`）：

anchor 生成 = `slugify(title)`，其中 slugify 默认把：
- 空格 → `-`
- 中文 → **保留原字**（不做转码/拼音）
- 特殊符号 → 删除

### 实测 anchor 样例

| 标题 | 生成的 anchor | 说明 |
|------|--------------|------|
| `# 有理数基础` | `#有理数基础` | 中文原样保留 |
| `## 一元一次方程的求解步骤` | `#一元一次方程的求解步骤` | 中文原样保留 |
| `## 研究背景` | `#研究背景` | 中文原样保留 |
| `### 函数图像教学研究` | `#函数图像教学研究` | 中文原样保留 |
| `# 研究问题` | `#研究问题` | 中文原样保留 |

**注意**：Content 生成的 anchor 是中文原文，**不是** slug（不是 "research-question" 那样）。

### 与页面 URL 的拼接

Content 默认 path（不强制小写时）：`/research/sample-research#有理数基础`

## 锚点稳定性矩阵（模拟测试）

| 场景 | 原 anchor | 改后 anchor | 稳定？ |
|------|-----------|-------------|--------|
| 标题不变 | `#有理数基础` | `#有理数基础` | ✅ |
| 标题加"正式" | `#有理数基础` | `#有理数基础正式` | ❌ 变了 |
| 文件重命名 | `/research/sample-research` → `/research/sample-research-v2` | anchor 不变 | ✅ anchor 稳定，path 变了 |
| 标题删"基础" | `#有理数基础` | `#有理数` | ❌ 变了 |
| 中文标题加标点 | `#有理数基础` | `#有理数基础！` → slugify 删标点 = `#有理数基础` | ✅ 标点被清除 |
| 标题中加空格 | `#有理数基础` | `#有 理 数 基 础` → slugify 空格变 `-` = `#有-理-数-基-础` | ❌ 变了 |

## 跨文档引用稳定性

如果 A 文档引用 B 文档的锚点 `/findings/F-0001#有理数基础`：
- B 文档标题不变 → anchor 不变 → 引用有效 ✅
- B 文档标题改了 → anchor 变了 → 引用悬空（E2 悬空引用）
- B 文档 docId 改了 → `/findings/F-0002#...` → 引用悬空（E4 幽灵注册）

## 建议

锚点稳定性**不是 Content v3 内置保证**，依赖 slugify(title) 的确定性。要保证稳定：

1. **不要频繁修改标题**（最简单）
2. 文档内关联用 docId（`F-0001`）而非 path + anchor 组合
3. validate-content.mjs 的 E2（悬空引用）会捕获 anchor 变化后的断链

## 结论

| 维度 | 实测 |
|------|------|
| 标题 anchor 生成规则 | slugify(title)，中文原样保留 |
| 标题不变时 anchor 稳定 | ✅ |
| 标题改动后 anchor 稳定 | ❌ 会变（无内置稳定 ID） |
| 跨文档引用可被 E2 捕获 | ✅ |
| V-3 状态 | 完成，锚点机制可接受，建议：标题一旦上线尽量不改 |
