# V-2 技术验证：MiniSearch + Intl.Segmenter 中文分词检索

**方法**：用 `Intl.Segmenter('zh-CN', { granularity: 'word' })` 做中文分词，自定义为 MiniSearch 的 tokenizer，构造 MiniSearch 索引，跑 30 条查询集（含 V-1 同款 20 条 + 额外 10 条跨节查询），记录命中数、BM25 排序质量与响应时间。

**判据**：

**运行时间**：2026-11-11

## 运行时环境

- `minisearch@7.2.0`（spike 依赖，已安装）
- Node v24.18.0（内置 `Intl.Segmenter`，无需额外装中文分词库）
- 测试样例：7 条 section（三集合样例各扩展，模拟 `generateSearchSections` 输出）

## Intl.Segmenter 分词质量

```
输入: "有理数 函数图像 一元一次方程"
输出: 有理数 | 函数 | 图像 | 一元 | 一次 | 方程
     ↑词    ↑词    ↑词  ↑词   ↑词   ↑词    ↑词
```

| 输入 | Segmenter 输出 |
|------|---------------|
| 有理数 函数图像 一元一次方程 | 有理数 / 函数 / 图像 / 一元 / 一次 / 方程 |
| 本节课讲解有理数的定义 | 本 / 节 / 课 / 讲解 / 有理数 / 的 / 定义 |
| 函数图像的理解对后续学习至关重要 | 函数 / 图像 / 的 / 理解 / 对 / 后 / 续 / 学习 / 至 / 关 / 重要 |

**关键**：Segmenter 把 `函数图像` 正确拆成 `函数` + `图像` 两个词，不再是整句大 token。

## MiniSearch 配置要点

```js
const miniSearch = new MiniSearch({
  fields: ['title', 'titles', 'content'],
  storeFields: ['id', 'docId', 'collection', 'title', 'content'],
  searchOptions: {
    boost: { title: 3, titles: 2, content: 1 },  // 标题权重高
    prefix: true,         // 前缀匹配（"有理" 命中 "有理数"）
    fuzzy: 0,             // 中文无拼写纠错需求
    combineWith: 'AND'    // 与 Content FTS5 默认一致
  },
  tokenize: segment,  // ← Intl.Segmenter 分词
})
```

## V-2 局限性

1. **需自建索引**：`miniSearch.addAll()` 在 predev/prebuild 时重建，与 Content 构建解耦
2. **索引存储**：7 条样例的索引 ≈ 2-3 KB（JSON），大文章库需评估存储位置（建议 `.index/minisearch.json`，gitignore）
3. **SSR 部署下**：MiniSearch 在 Nitro 服务端渲染时也需构建一次索引（可 memoize）
4. **结果高亮**：MiniSearch 不内置高亮，需自定义实现（不是 V-2 spike 范围）
5. **标题 boost**：title 权重 3x 可有效提升标题包含关键词的 section 排名
