# V-4 技术验证：体积与性能

**方法**：从 build 输出提取关键 chunk 大小、gzip 大小与构建时间。

**判据**：Owner 未裁（D2），只报告实测值。

**运行时间**：2026-11-11（V-6 spike 含 remark-math + rehype-katex 的 build）

## 分析

### Nitro server 体积

- `server/index.mjs` = 1.8 kB（主入口极轻）
- `server/chunks/build/` = SSR 运行时 + Content 模块
- better-sqlite3 native binding 是最大块（~1.5 MB），nitro 会自动打包

### precomputed.mjs 189 kB 分析

这个 chunk 包含：
- Content schema 定义（三集合 frontmatter 规则）
- 三集合样例内容（markup + frontmatter）
- FTS5 搜索表 schema
- registry.yaml 3 条登记

189 kB 对 SSR 来说可接受。正式上线后文章量增大时需关注这个 chunk 的增长。

### 优化空间（非 V-4 范围）

1. Content 生产模式：`dev: false` 时 Content 可能减小 schema 体积
2. `virtual/styles.mjs`：手动拆分组件样式 chunk，减少首屏 CSS
3. KaTeX CSS 单独 split chunk：当前 0.1 MB，引入后需评估是否异步加载

## 结论

| 维度 | 实测 |
|------|------|
| Build 时间 | 14.1s（含 V-6 插件） |
| Total gzip | 10.4 MB |
| 首屏关键路径 | entry 60.9 kB + precomputed 8.44 kB |
| TBD TTFB | 未实测（需部署到 Vercel 或本地 preview + curl 测 Time-To-First-Byte） |
| V-4 状态 | 完成，体积可接受 |
